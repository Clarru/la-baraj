# Interactive prop transfer: 2048 cabinet

The third case transfers the accepted wood/iron PBR family to an original item, rather than reconstructing a particular Quaternius mesh. See [the working case](../../../../experiments/asset-skill-lab/arcade/README.md). The cabinet concept is inspiration; measured authored dimensions are the export contract. A bounded coordinated shared-preview browser pass is now complete for local SharedWorker practice; the extension remains unranked and local until the compatible Worker is intentionally released and production deployment is accepted.

1. Separate the static shell from functional surfaces and mechanisms before modeling. Keep semantic `Screen`, `Joystick`, `ButtonNew` and `ButtonScores` nodes. Bake transforms deliberately; retain real pivots. A blanket static-mesh join destroys interactive parts. Mesh quantization can also recenter a mesh node; a separate semantic parent preserves the true hinge. The cabinet tests its decoded joystick pivot at y0.967m and keeps the handle mesh beneath it.
2. Reuse existing material profiles, not every surface indiscriminately. The first green-tinted iron atlas looked mottled and stone-like. A small original painted-timber color map supplied the needed grain; normal and packed reflection data remain shared. Restraining a normal map's strength can suit paint without deleting its surface information.
3. Check the actual exported shader. Blender's MixRGB multiplication was not preserved as the expected glTF color factor. The case explicitly authors a valid glTF material/texture transform and re-imports it. Never infer runtime appearance from the Blender source alone.
4. Physical controls need clearance in the focused camera. The initial joystick intersected the display's visual area; the first marquee overhang clipped the screen header. Move controls outside the grid's projection and test the full screen from the player's eye. Check narrow viewports as projections as well as the orthographic turnaround. The runtime focus formula is aspect-aware. The actual browser pass exercised the Game's 48° FOV at desktop and narrow fine-pointer sizes; the earlier 50° Blender studies remain projection evidence, not browser evidence.
5. Live surfaces require UVs even when their placeholder material has no texture. Configure pruning to retain vertex attributes. Blender-exported glTF screen UVs use a top-left image origin here; the CanvasTexture has `flipY=false`, and pointer UVs map directly to the logical canvas. Verify orientation from the actual GLB instead of assuming it from a Three plane.
6. Meshopt may cyclically rotate triangle indices. Repeated minima in degenerate triangles make `indexOf(min)` a false winding alarm. Compare the lexicographically smallest of all three cyclic rotations; never sort a triangle's vertices, which would erase winding evidence. Attributes and data-map pixels still require exact decoded comparison.
7. Keep private material clones for the prop. Use the existing renderer-cached lake environment on its materials, without changing the scene environment or the generic loader's global roughness/metalness policy. Cache the material list rather than traversing the whole model each frame.
8. Generate a live display in code. The image reference is not a playable screen. The case renders a CanvasTexture on the real mesh, uploads only while dirty/animating, caps uploads at 30Hz, and removes tile/hardware motion under reduced-motion preferences. Keep native semantic controls available to assistive technology using the same actions. When terminal states overlap, resolve the interaction in product order: an uncontinued win gets **Keep going** before a no-moves fallback can offer **New game**; keep the same precedence in screen hit regions, keyboard/controller actions and the accessible action list.
9. Treat resource limits as application semantics, not as a billing promise. Ranked persistence now allows 50,000 successful logical saves per UTC day across ranked owners; an optional `{ day, count }` meter travels in the same owner row as board, best and request history. The save is counted only after the owner row succeeds, with no separate counter write. Reads, unchanged moves/resumes, already-continued wins, duplicate requests and failed writes are free; local unranked practice bypasses the meter. Legacy rows, restart recovery, UTC rollover, failed-save retry, rename/continue, no-op/read/dedup exclusions, concurrent last-slot attempts and fire continuity are covered by the backend correction. At the cap, the short safe error leaves the accepted board, best, revision and request history untouched.

Asset evidence and product evidence are different gates. Blender renders demonstrate geometry, UVs, material response and camera projection. Canvas captures demonstrate the authored display. Neither alone proves browser input, networking, FPS or publication. The actual-world browser record now proves the bounded local-preview route: E entry, camera/world continuity, local avatar hiding, arrows/WASD, mesh drag, pointer controls, N plus Enter/Space, Escape contexts, two private local boards, Local records, exact personal resume and settled full reload. It does not prove production ranking or deployment. Genuine mobile-UA/touch behavior, reduced-motion media emulation, a browser-reached win, same-owner stale-tab racing and storage-failure injection remain unrun in the browser; corresponding DOM, hook and Worker logic is covered by tests. A `240 KB` encoded GLB also does not mean `240 KB` decoded GPU memory.
