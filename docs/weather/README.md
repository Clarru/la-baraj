# Lake Cinciș weather

La Baraj uses Open-Meteo's modelled current weather near **45.69° N, 22.85° E**, within the documented lake shoreline. The current cloud-cover percentage and WMO weather code drive one shared weather state. Model output represents a grid cell and can differ from conditions on the shore; it is not a live camera or a local weather station. The data is credited to [Open-Meteo](https://open-meteo.com/) and [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) in the game menu, alongside the model time in Romanian local time.

The existing world Durable Object fetches on player connection or a lightweight client refresh request. Concurrent requests share one fetch. Successes are cached in the same Durable Object's separate `lake-weather-v1` key for 15 minutes; failures retry no sooner than five minutes. With players present throughout a day, successful operation is at most roughly 96 provider requests per day, regardless of player count; provider outages can trigger up to roughly 288 attempts per day. No new service, credentials, paid plan, recurring server alarm or player-location data is required. The cache survives hibernation, leaves home/fire/Planes records and their alarms untouched, and makes no requests while nobody is connected.

If the provider fails, the last valid model result remains available for up to three hours from the earlier of its model time and fetch time. It then becomes unavailable and the scene gradually returns to the normal day/night palette. The same freshness deadline is enforced on the client in case the connection drops. Malformed, implausibly old or future provider data is rejected. Open-Meteo's output uses 15-minute model data and is refreshed at most every 15 minutes by the world; weather is therefore near-current rather than instantaneous.

Cloud cover blends over 25 seconds into the sky, light, fog, distant landscape and water. A small shared procedural texture draws cloud shapes with one texture lookup and no new scene geometry. The menu reports clear, partly cloudy, cloudy, fog, rain, snow or thunderstorms according to the provider. This first visual iteration represents cloudiness and light; it does **not** yet simulate falling rain, snow, wet ground or thunder.

Verification: automated tests cover response validation, 50 simultaneous refreshes, retry throttling, persistence across a Worker wake, stale fallback, WMO labels, client expiry and smooth visual transitions. Two isolated browser players saw the same weather and unavailable fallback. Local desktop synthetic 49-walker / 50-cabin tests at 1707×960 and DPR 1.5 measured approximately 71.7 fps clear and 71.3 fps cloudy over 600 frames. This is a rendering comparison, not a network load guarantee. The temporary browser weather controls and visual overrides are available only in opt-in local test builds, never the production bundle.

References: [Open-Meteo weather variables and WMO codes](https://open-meteo.com/en/docs), [free noncommercial terms and limits](https://open-meteo.com/en/terms), [Cloudflare Durable Object lifecycle and hibernation](https://developers.cloudflare.com/durable-objects/concepts/durable-object-lifecycle/).
