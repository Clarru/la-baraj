## First pass findings and correction batch

The initial pass found three product defects:

1. Exiting fullscreen while the native Menu dialog was open left that dialog above the resume screen. The correction closes menu/chat when the mobile gate blocks the game. The confirmation pass used an actual fullscreen exit, verified the dialog was gone, hit-tested the resume button and tapped it to resume the same mounted world.
2. 2048's automatic grid rows produced unequal cell heights, and the float-based landscape layout let the arrows overlap the board. The correction uses equal rows and a two-column landscape grid. Confirmation measured equal square cells in both orientations and separate board/control bounding boxes, then moved tiles from the controls.
3. Nearby bench prompts exposed Sit while hiding the keyboard's secondary fishing/fire action. Activity prompts now supply explicit secondary actions and seat-shift availability. Confirmation cast a line beside Sit, waited for a real bite, reeled, cancelled another cast, put out the campfire and started relighting it from touch.

The confirmation also verified that a simulated physical W key remains held while touch triggers Jump, the jump pulse expires, 320px controls do not overlap, and a denied fullscreen request offers a browser fallback that reaches the actual touch game.

The initial automation required corrections to its driver: hidden diagnostic outputs must be awaited with `state: attached`; clipped assistive controls require scoping actions to the visible mobile board; swipe dispatch needs ordered events; and a fishing bite must be awaited within the same cast cycle. These driver issues are separate from the three product defects above.
