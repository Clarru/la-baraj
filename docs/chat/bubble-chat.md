# Temporary player chat

Enter opens the editor above the local character. Text appears live above that player for others, without a send button or stored chat history. Enter sends the current text, ends typing, and starts a fresh five-second display timer; an empty Enter closes the editor. Shift+Enter inserts a new line at the caret. Repeated Shift+Enter on an empty line does not add blank padding or erase the preceding text. Leading and interior blank lines are removed from pasted or edited drafts. Starting a third populated line removes the oldest, and wrapped text scrolls to show the latest two visual lines. The empty editor starts at one line and grows to two lines only when the text needs it. Escape closes it immediately. Five seconds without an edit closes the editor and clears the bubble, restoring movement controls. Clicking outside the editor ends typing immediately, starts a fresh five-second display timer for both local and remote players, and allows walking while the bubble follows the character. Escape clears the visible bubble immediately. Enter opens a fresh empty editor while the previous message is still visible, clearing that abandoned draft locally and for other players; existing buttons and forms retain their normal Enter behavior.

The editor uses the village's parchment and forest-green palette in a rounded speech bubble and expands from 66px to at most 240px as text grows. Text and placeholder `#20352b` sit on a solid `#f3e5c9` surface: **8.41:1**, above WCAG AA's 4.5:1 requirement for normal text. A dual-color focus indicator is visible on varied scenery. The input has an accessible name and screen-reader instructions. This is a contrast and keyboard check, not a full accessibility certification.

Chat events are ephemeral: only the connection's identity and a rate bucket live on the server; message text is not stored in snapshots, the database, or chat logs. The wire format accepts at most 180 UTF-16 units and two explicit lines, permits ordinary Unicode, rejects control characters, and throttles excessive input. The client sends updates after a short 150ms debounce and independently expires messages after five seconds, including if a sender disconnects.

[FigJam cursor chat](https://help.figma.com/hc/en-us/articles/1500004414842-Send-messages-with-cursor-chat) likewise streams text and shows it for five seconds after typing stops. In La Baraj, Enter finishes the current message and Shift+Enter adds a line; clicking outside remains an alternative way to finish typing.

Verification: two isolated browser players saw text as it was typed, the newest two lines after a third explicit line, and immediate Escape clearing. A five-second idle test removed both bubbles and restored WASD. Keyboard testing confirmed W and R enter text while chat is focused rather than moving or resetting the character. Short and long messages were checked at desktop sizes; mobile remains outside the current project scope. The user-confirmed tree work remains in its own draft branch and its assets are unchanged.

A local 600-frame rendering fixture with 49 nearby walkers and 50 cabins measured about 99 fps (p95 13.5ms) at 1707×960 and DPR 1.5 on the test machine. This is a single local rendering sample, not a network load test or a guarantee for other hardware.

Click-away verification used two isolated players: after typing, clicking the world stopped editing, kept the bubble visible for both players and allowed immediate walking. A timed check waited three seconds before clicking and another three after; the message remained visible, then cleared five seconds after the click. Reopening previously retained the text; the October 30 revision deliberately replaces that behavior with a fresh empty draft. Escape still clears a lingering bubble immediately.

October 30 draft regression checks: seven normalization cases cover empty Enter, repeated Enter, leading/interior blank lines, pasted CRLF, control characters, Unicode and the existing wire limits. A mounted DOM fixture additionally checked rapid click-away/reopen, cancellation of a pending update, preservation of the lingering message until reopening, Escape, and five-second idle expiry. The full 314-test suite and production build passed.

Enter-to-send regression checks cover immediate publishing before the debounce, the five-second display timer, native Shift+Enter behavior, sending two lines, click-away, fresh reopening, empty submission, held Enter and IME composition.
