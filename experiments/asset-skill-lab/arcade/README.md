# 2048 — transfer case and finalized playable cabinet

An original upright cabinet tests whether the measured prop workflow transfers to a new interactive item. It uses the accepted timber/iron PBR family, a small original forest-green painted-timber map, semantic moving parts and a real mesh screen. The game is implemented in the existing React/R3F stack. No Undo control or operation exists. The extension is additive: it does not replace the world, the existing multiplayer games, or the global visual contract.

The decoded cabinet measures approximately **0.760 × 0.724 × 1.913 m** (nominal contract: 0.76 × 0.72 × 1.92 m). The shipping GLB is **245,680 bytes**, **7,082 triangles**, five mesh objects and 13 primitives. Four embedded PBR maps are at most 512×512. The display's 768×960 CanvasTexture is created at runtime, not embedded in the shipping GLB. NodeIO tests independently decode [`apps/web/public/assets/arcade2048/cabinet.glb`](../../../apps/web/public/assets/arcade2048/cabinet.glb), verify the size/geometry budget, screen UV orientation and retained nodes. [`optimization.json`](optimization.json) records exact decoded Meshopt attribute/winding and normal/MR pixel preservation.

## Product behavior

Walk to the machine at the east edge of the gathering area (x12, z70.3753), then press **E** or click. Arrows/WASD and screen/joystick swipes move tiles. **N** opens New game, **L** opens records. Escape returns from a screen page or leaves; the screen also has a Leave button. New game confirms before discarding an active run. An uncontinued 2048 win always takes priority over the no-moves condition: **Keep going** continues the winning run even when that board is full, while a continued blocked board offers **New game**. Best score survives either path.

Each cabin owner has one private board and personal best. The Worker applies the rules, generates random spawns, computes score and persists one owner row before acknowledging a changed move. Each row includes the personal best; the global top ten are derived from those records. No endpoint accepts a client-submitted score. A revision rejects a stale second tab, and recent request IDs deduplicate retries. Failed writes leave the last accepted board untouched. Personal replies go only to their requester. Public records include nickname, rank, best score and highest tile, without home credentials.

Production persists `arcade2048-v1:<housing epoch>:<owner>`. This does not modify home, fire, Planes or Cruce records. There is one small write per changed move/new game/continue, plus a rename write when needed; unchanged moves return the accepted view without a spawn or write. There is no per-frame persistence, global snapshot rewrite or new service. A load failure disables the arcade for that Worker wake while retaining its stored rows. Local SharedWorker preview is explicitly unranked practice, uses local records, and lasts for that local world's lifetime.

## Integration and release

Changes to Game, CameraRig, protocol and multiplayer are additive. Existing games retain their owners and hooks. The avatar remains in place and is hidden only locally during focus, preventing its torso from covering the screen; other players still see their normal avatar. The camera focus blends over 0.5 s and uses an immediate transition when reduced motion is requested. Tile slides/merge pops and physical button/joystick feedback run for 150 ms; Canvas uploads occur only while dirty or animating and are capped at 30 Hz. Scoped material clones reuse the renderer-cached lake reflection environment. The GLB loads within 65 m under its own Suspense boundary, without adding it to the initial world-loading gate.

The server advertises `features.arcade2048` in its snapshot. A newer frontend sends no arcade messages to an older Worker. Release owner must deploy the compatible Worker intentionally before accepting live arcade play; this feature does not deploy itself or change origins. Never run another preview server. Browser gameplay, paired-player rankings and publication require the sole-writer slot on the shared 4173 preview; browser acceptance is still pending for this extension, so this document makes no claim that shared-4173 QA or deployment occurred. Projection renders are explicitly not browser evidence.

## Art process and reproducibility

[`reference.webp`](reference.webp) preserves the selected generated concept, not a runtime screen skin. [`paint-512.png`](paint-512.png) is the selected original paint map. [`build_cabinet.py`](build_cabinet.py) creates editable named components in `Arcade2048.blend` and an export. [`finish_cabinet.mjs`](finish_cabinet.mjs) explicitly sets the paint material and prepares the QA clone; [`optimize_asset.mjs`](../../../.agents/skills/la-baraj-3d-assets/scripts/optimize_asset.mjs) produces the shipping file. The source `.blend`, generated masters and intermediates stay local and can be regenerated. The direction brief is [`arcade2048.md`](../../../.impeccable/briefs/arcade2048.md); the accepted public UI asset family is documented in [`docs/art-direction/ui/README.md`](../../../docs/art-direction/ui/README.md).

Run `ASSET_LAB_BLENDER=/absolute/path/to/Blender ./experiments/asset-skill-lab/arcade/reproduce.sh` from the repository root. The QA canvas renderer additionally needs an installed `@napi-rs/canvas` path through `ARCADE_QA_CANVAS_MODULE`; that dependency is not bundled into the game. Font conversion uses Python fontTools. The source web fonts and trim bake are already in the repository. The script does not start or replace any server.

The documentation review reran the three focused frontend files (7 tests), `npm run test:protocol` (10 files, 136 tests), `npx tsc --noEmit`, and `npm run server:check`. No browser gameplay, paired-player ranking, shared-4173, FPS, or publication check was run in this pass.

The first render exposed an open roof, missing exported paint tint and a joystick overlapping the board. The next exposed a marquee/camera clearance issue and overly mottled paint. Geometry clearance and a matching painted timber map resolved those named defects. A later finish review found that a full board containing a newly won 2048 tile was taking the no-moves path; the controller, screen hit-test and assistive action now prioritize the uncontinued win, with a regression test preserving that behavior. The reusable process lessons are retained in [`interactive-props.md`](../../../.agents/skills/la-baraj-3d-assets/references/interactive-props.md). This is a coherent transfer case, not a claim of identity with the generated concept or a measured FPS result.
